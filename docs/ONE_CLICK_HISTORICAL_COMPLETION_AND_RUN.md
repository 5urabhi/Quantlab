# One-click historical data completion and model run

## Purpose

The selected historical model must not require a separate download click,
refresh and second run click when the **same authorized user action** can do
those steps safely. **Models -> [historical model]** now shows
**Get missing history (+20%) & run** whenever the selected original Dhan
stock or multi-asset input is extendable to the preferred sample target.

The primary button triggers a single explicit, read-only-with-respect-to-broker-
orders POST, `/api/lab/data-requirements/extend`, with
`confirm_download=true` and `run_after_download=true`.
There are **no provider requests on page load or GET/readiness inspection**.

The download-only action remains available under **Data options** for users
who want to prepare history without fitting the model.

## Exact steps

1. Identify the selected dataset and model. For single-series fits, respect
   the exact selected ticker, or display the **named recommended stock** in
   the UI before a user clicks the one-click action. Never silently substitute
   a different stock or label Dhan index spot as original dividend-inclusive TRI.
2. Check source SHA-256 and reuse matching cached original candles. The
   source planner identifies uncovered calendar windows, with Dhan as the
   primary provider. Download only uncovered original daily history through
   the locally configured, authorized Dhan account. All provider errors,
   unavailable sessions and timestamp anomalies still fail closed.
3. Append the observations into the canonical `dhan_shared` research source,
   leaving original prepared batch snapshots untouched. Recompute the
   model's observed return count and the required minimum and preferred
   **+20%** buffer.
4. If the minimum remains unsatisfied, return **incomplete** with a documented
   source blocker; do not fit or save a model. If the minimum is met, calculate
   the registered Python model with the exact observed source and mapped
   stock identity; save the actual run and navigate to **Results & Charts**.
   A missing preferred buffer, when minimum has been reached, remains
   separately visible as **minimum_ready**, not a claim that it was acquired.
5. The existing global jobs queue shows progress and supports safe
   cancellation between operations. No broker orders or simulated market
   prices are generated by this workflow.

## Verification / expected Heston case

On the November 21 local data, the Heston historical variance proxy had
224 observed stock returns versus a 252-return minimum and a 303-return
preferred target. The prior UI showed a standalone
`Complete recommended stock (+20%)` action, followed by a separate run.
Select **Models -> Heston historical variance proxy** and click the new
primary **Get missing history (+20%) & run** action for the displayed
recommended FEDERALBNK instrument.

The original research machine and valid local Dhan token are required to
prove actual results. GitHub Actions tests use isolated mock sources and
must not be reported as a successful vendor download.

After the job completes, independently run
`bash run.sh verify-saved --dataset dhan_shared` locally to re-audit the
entire 35-model catalog; the read-only verification command does not
implicitly call any market provider.

## Scope boundaries

This workflow fetches **original historical candles**, when a configured
provider really makes them available. It cannot reconstruct historic
20-level order-book packets, produce previously unrecorded historical
option bid/ask snapshots, invent exchange sessions, certify a trading
strategy's actual filled P&L, or obtain NIFTY TRI from Dhan spot candles.
Such sources require separately eligible provider access, previously
recorded genuine packets or a reviewed import.

The existing Data Center acquisition planner separately supports an
**explicitly authorized** Zerodha secondary source when Dhan fails
transiently and exact Kite/Dhan instrument mappings and source checks pass.
The Models one-click path does not silently activate that optional fallback.
