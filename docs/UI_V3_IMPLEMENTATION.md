# QuantLab UI V3 implementation and acceptance

This is a local-first research application. The new graphite/amber visual system is scoped to the existing V2 shell. Green/red remain semantic market and status colors. No broker order path has been enabled.

## User workflow
- Global Python opens a resizable workspace from any route; it preserves draft state across navigation.
- My scripts persists named code, category and immutable revisions to local SQLite in data/quantlab_scripts/library.sqlite3. Save uses optimistic revision checks. Save as new retains history. Existing browser-saved strategies can be imported, and code can be exported as .py.
- Python analysis on compatible research and market charts attaches the displayed fixed snapshot; the option chain and Data Explorer expose contextual snapshots too. The chart sandbox accepts analyze(data), with title, x_label, y_label and aligned finite-or-null traces. Source rows are not overwritten. The custom output is saved locally and labeled user-snapshot analysis. A companion chart or same-unit overlay may be attached only while the originating snapshot still matches. The editor uses lightweight syntax highlighting, not an external IDE package. A strategy opens the existing causal strategy editor, which uses completed historical/live candles.
- Run snapshot uses the existing local research queue and mandatory bubblewrap/prlimit subprocess. Only the copied input and script are mounted. Standard-library or optional scientific system-package profile. Settings → Python Environment reports package files and performs a real isolated import probe. Privileged package installation remains manual. No unsafe fallback, broker credentials or order permissions.
- Automatic recorder uses the existing token/setup and persisted disarm rules. In Trading -> Order Book, select an automatically captured contract to inspect its latest saved original book. This does not start another broker socket. A manual ticker may be stopped while automatic capture is armed; the UI must not call those saved samples live signals.
- Trading -> More tools contains Options Analytics and Directional Trading, alongside the existing chain/strategy paths. Existing routes and paper trading remain available.

## Acceptance
- Existing React build, Python tests and Chromium acceptance suite must pass on the final head. New tests cover script version history, input/output validation, fail-closed sandbox, compact navigation and saving reusable code.
- Verify actual Dhan token validity, local namespace permissions, market-hours capture and real source coverage on the user's Ubuntu machine; CI uses synthetic fixtures only.
- Strategies → Running Python supports version-pinned background calculations on new recorded index minutes, option-chain receipts and recorded spot receipts. Monitors pause on restart and require explicit resume. The index and option views show refreshing custom results. Custom model and scanner libraries reuse the snapshot interface. A scanner ranks source rows by its first numeric trace. Multi-leg spread candidates can be scored from attached snapshots. These are custom research calculations, not native built-in model registry entries, certified trading signals or broker execution.
- No automatic privileged package installation or arbitrary virtual environment mounting. Scientific imports require system-distribution packages and functioning local Linux sandbox permissions.
- Chart improvements include shared research figures, actual OHLC when supplied, separate irregular REST spot receipts, advanced option plots, EMA backtest figures, equity/underwater and spread history/payoff, saved relative views, surface heatmap and paired CE/PE chain with a contextual contract drawer. The remaining historical options equity, signed-index balance, paper liquidation marks, original data-close charts, microstructure metrics, option quote timelines and candle views now use the same renderer. Depth curves use cumulative step geometry. Browser acceptance captures every default route; human visual review of the screenshots remains separate. Classic remains available as a compatibility fallback.
- Simultaneous true index-tick recording and automatic option capture remain dependent on the provider's socket allowance and documented index packet format. REST receipts are displayed as receipts rather than candles. No additional subscription or undocumented packet decoding is introduced.

## Extended Python and local workflow implementation
- Projects / Research Notebooks: versioned Markdown and Python cells, copied input snapshots, ordered isolated run or run-through-cell, persisted outputs, cancellation and notebook export. Not a long-lived unrestricted Jupyter kernel.
- Model Catalog: registered custom Python models have native cards and input selection (local source table or explicit theoretical parameters); results remain separate from validated built-ins. Saved script revisions are pinned per run.
- Spread discovery: run saved scanners on displayed candidate snapshots and optionally re-score changed inputs while the page remains open. Candidate feasibility and source checks are unchanged.
- Live charts: select compatible running indicators; exact source values and timestamps must match; same-unit overlays or separate linked panels. Stale/mismatched calculations are not shown as current.
- Shared option socket: spare subscription slots may be used for documented index ticker responses, no extra socket and no option displacement. Undocumented packets remain unsupported; real provider acceptance required.
- Navigation searches every configured route; Data Explorer has a source-record drawer with immutable row export and contextual Python action.
- Eligible token renewal consent can be changed while recording. Privileged package installation uses an explicit interactive local allowlist helper (`bash run.sh python-packages install`), not arbitrary backend package commands.
- Acceptance requires final-head CI, screenshot review of all routes, actual Ubuntu isolated imports and authenticated Dhan market-hours packet checks. These have not yet been certified on the final revision.
